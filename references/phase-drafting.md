# 写正文

每次只写一章。这里的规则适用于所有风格。具体的语气和禁用词看项目的 `styles/<id>/`。

## 写前

1. 运行门禁，读完它打印的必读清单：

```bash
cws gate --project . --stage draft --chapter N --agent 你的名字
```

2. **读上章结尾**：时间、地点、谁在场、伤情、情绪余波，以及上章的钩子。
3. **读本章细纲**：事件、视角、钩子、接钩、要动的伏笔。
4. **查信息差**：本章每个人此刻知道什么，不知道什么（`canon/knowledge.json`）。
5. **查名字**：只用 `canon/` 里的名字。需要新人物时，起一个能用的名字，写进 `new_canon_requests`。

## 写时

- **接住上章**：开头直接写下一个动作，不复述上章。
- **锁定视角**：一场一个视角，只写这个人物能感知到的东西。
- **对白有潜台词**：人物不要想什么说什么。
- **守住物理状态**：受过的伤、消耗的东西、身上的衣服都要连得上。这一点的严格程度随题材变化，古言战斗比爱情喜剧严。
- **照风格写**：只用选定风格的手法。`cn-webnovel` 的场景三问和道具质感，不适用于 `en-romcom`。
- **结尾执行“半拍截断原则（Mid-Action Cut）”**：绝对禁止让动作完整落地后收笔（如脱鞋上床、打开表格、送完文件）。必须在动作执行到一半被意外打断、新危机迫近或秘密引爆的瞬间硬性掐断！不给读者文学饱腹感，只给付费翻页的生理饥饿感！不总结，不升华。

## 写后

1. 落盘前试查，或落盘后检查：

```bash
cws check --project . --chapter N --file 草稿路径
cws check --project . --chapter N
```

2. 修到退出码为 0。告警逐条看，能修就修，不修的要说明原因。
3. 写 `state/deltas/ch-NNN.json`（字段见 `references/canon.md`）。
4. 向用户或审稿汇报：路径、字数、钩子类型和强度、新正典请求、未修的告警。

## 文件位置

正文放 `project.json` 的 `chapters.glob` 指定的位置。默认是 `chapters/ch-001.md`，第一行写 `# Chapter 1: 标题` 或 `# 第1章 标题`。标题行不计入字数和校验。
