# 审稿和单元复盘

审稿人不写这段正文，也不改它，只给结论。脚本只能查规则能查的东西，判断好不好看是审稿人的工作。

## 单章或单批审稿

先跑脚本：

```bash
cws check --project . --range 21-30 --strict
```

脚本未通过直接打回。通过后读正文，查脚本查不出的问题：

| 项 | 问题 |
|---|---|
| 一致性 | 人物是否按 `canon/` 说话和行动？称呼对吗？ |
| 信息差 | 每个人的言行是否符合他此刻知道的？脚本只查增量里申报过的，没申报的要靠人看 |
| 连续性 | 伤情、物品、时间、地点是否接得上？ |
| 钩子 | 章尾真的让人想翻页吗？开头真的接住了吗？ |
| 语气 | 符合 `styles/<id>/voice.md` 吗？有没有用力过猛？ |
| AI 腔 | 有没有词表之外的套路：排比、对仗、每段都收一句漂亮话 |
| 增量 | 状态增量是否如实反映了正文？有没有漏报新人物 |
| 红线 | 有没有违反 `[核心红线]` 和平台合规项 |

打回时写明章号、位置和问题，不要代写。

## 单元复盘（每 10–15 章）

```bash
cws check --project . --range <本单元> --strict
cws merge --project . --agent <账本角色>
```

1. 对照情绪地图或改写说明：主线是否跑偏？情绪有没有起伏？
2. 对照 `threads.json`：有没有接近超期的伏笔？
3. 对照 `knowledge.json`：下一单元开始时，每个人知道什么？
4. 对照结局：本单元有没有写出和结局矛盾的事实？发现后加进 `contradiction_patterns`。
5. 处理账本里的 `pending_canon_requests`。
6. 把反复出现的问题写进 `project.json` 的 `extra_banned`，让脚本以后自动拦下。
